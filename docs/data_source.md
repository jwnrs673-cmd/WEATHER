# データ源の仕様と制約

## 取得元

気象庁「過去の気象データ検索」 <https://www.data.jma.go.jp/obd/stats/etrn/index.php>

| 用途 | URL |
|---|---|
| 県内の観測地点一覧 | `select/prefecture.php?prec_no={府県番号}` |
| 官署の日別値 | `view/daily_s1.php?prec_no={府県番号}&block_no={観測所番号}&year={年}&month={月}&day=&view=` |
| アメダスの日別値 | `view/daily_a1.php?prec_no={府県番号}&block_no={観測所番号}&year={年}&month={月}&day=&view=` |

文字コードは EUC-JP です。`fetch_jma._get` で明示的に指定しています。

通常は `stations.load_stations` が府県地図ページから全地点を読み取ります。

## 官署とアメダスの違い

これがレポート設計上いちばん重要な制約です。

| 項目 | 官署 (`daily_s1`) | アメダス (`daily_a1`) |
|---|---|---|
| 気圧 | ○ | × |
| 降水量（合計・最大 1 時間・最大 10 分間） | ○ | ○ |
| 気温（平均・最高・最低） | ○ | ○ |
| **湿度（平均・最小）** | **○** | **×** |
| 風速（平均・最大・最大瞬間）と風向 | ○ | ○ |
| 最多風向 | × | ○ |
| 日照時間 | ○ | ○ |
| 降雪・積雪 | ○ | 地点による |
| **天気概況（昼・夜）** | **○** | **×** |

**湿度を観測しているのは官署だけ**です。多くの県で官署は 1〜3 か所しかないため、
「県内全地点の湿度一覧」は原理的に作れません。レポートでは代表地点（地方気象台）の
湿度を掲載し、アメダス地点の表からは湿度列を外しています。

## 値の記法

`parse_jma.parse_number` が解釈します。

| 記号 | 意味 | 本ツールでの扱い |
|---|---|---|
| `12.5` | 正常値 | そのまま数値化 |
| `12.5 )` | 準正常値（許容範囲内で資料が欠けている） | 数値化し、記号を `flags` に残す |
| `12.5 ]` | 資料不足値（欠測回数が許容範囲を超えた） | 同上 |
| `#` | 値が疑わしい／対象資料が不足 | 同上 |
| `--` | 現象がなかった | 積算量（降水量・降雪・積雪・日照）は `0.0`、それ以外は `None` |
| `×` | 欠測 | `None`、`flags` に `×` |
| （空欄） | その項目を観測していない | `None` |

`flags` は `daily.csv` の最終列に `precip_total=)` のような形で出力されます。

## 列構成の判別

日別値の表は地点によって列数が変わります（雪を観測しない地点は降雪・積雪の
2 列が無い、など）。そのため**位置の決め打ちではなくセル数で列並びを判別**しています
（`parse_jma.LAYOUTS_BY_WIDTH`）。

定義済みの列数は次のとおりです。

| 種別 | 列数 | 定数 |
|---|---|---|
| 官署 | 21 | `LAYOUT_OFFICIAL` |
| アメダス（雪あり） | 16 | `LAYOUT_AMEDAS` |
| アメダス（雪なし） | 14 | `LAYOUT_AMEDAS_NO_SNOW` |
| アメダス（最多風向なし） | 15 | `LAYOUT_AMEDAS_NO_PREVAILING` |

未知の列数に出会うと警告を出し、先頭から読める範囲だけを解釈して処理を続けます。

### ⚠️ 実ページに対する未検証事項

本リポジトリのパーサは、**気象庁の実ページの HTML に対してはまだ検証されていません。**
テストは実ページの構造を参考に組み立てた合成 HTML（`tests/fixtures/`）に対する
ものです。開発時のネットワーク制約により実ページを取得できなかったためです。

初回に実データで実行する際は、以下を確認してください。

1. **警告ログを見る**
   `未知の列数 N です` という警告が出たら、その列数に合う定義を
   `parse_jma.LAYOUTS_BY_WIDTH` に追加します。

2. **キャッシュした HTML と突き合わせる**
   `data/raw/{県}/{年月}/` に取得した HTML がそのまま残ります。
   ブラウザで開いて、生成された `daily.csv` の値と一致するか数日分を確かめます。

3. **特に確認したい点**
   - 官署の列が 21 列であること（気圧 2・降水 3・気温 3・湿度 2・風 5・日照 1・雪 2・概況 2 ＋ 日）
   - アメダスに「最多風向」列があるかどうか
   - 風向が数値ではなく文字列（「南南西」など）で入っていること

4. **地点探索が働いているか**
   `config/stations/{県}.json` に県内の全地点が並んでいれば成功です。
   1 地点しか無い場合は探索に失敗してフォールバックした状態なので、
   府県地図ページの HTML 構造（`viewPoint(...)` の形）を確認してください。

## 統計値の注意

- 月合計・月平均は**欠測日を除いて**算出しています。欠測がある地点では月降水量や
  月間日照時間が実際より小さく出ます。`MonthlySummary.observed_days` に項目ごとの
  有効日数を持たせています。
- 「熱帯夜」は本来「夜間の最低気温が 25℃ 以上」ですが、日別値からは日最低気温で
  近似しています。統計としては一般的な扱いです。
- 気象庁の統計値は品質管理の結果、後日修正されることがあります。レポートには
  作成日時を記載しています。

## サーバへの配慮

- リクエスト間隔は最低 1.5 秒（`fetch_jma.REQUEST_INTERVAL`）
- 取得した HTML は `data/raw/` にキャッシュし、再実行時は再取得しない
- User-Agent に用途と参照先を明記
- 九州 7 県を全地点で取得すると数百リクエストになります。まずは
  `--max-stations 3` で試すことを勧めます。
